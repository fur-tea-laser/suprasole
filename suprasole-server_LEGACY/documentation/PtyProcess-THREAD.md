* **`RunWorker` charter:** observe termination, collect, transition — the only code that writes `State_state` or collects the PTY process (issue §3C).
  * **Wake-up:** `RawConn.Read` on the pidfd. The callback returns `false` — park until readable — only when the pidfd is not readable, as the `RawConn` contract requires, so the netpoller's trigger mode never matters.
  * **`peek__TerminationReport_PtyProcess`:** the peek, `waitid(P_PIDFD, WEXITED|WNOHANG|WNOWAIT)`, which reads a termination without collecting it.
    * **A `waitid` error** can only be `ECHILD` (something else collected the process) — a real kernel case that the exclusive-reaping invariant (issue §5B.2) rules out. It has no branch in the source: it falls into the chain's final `else`, which lists it and panics. `EINTR` cannot occur: every call passes `WNOHANG`, and `wait(2)` raises `EINTR` only without it.
    * **Nothing reportable, `POLLIN` set:** `WITHHELD` — the process terminated, but a tracer holds the zombie ("a zombie ptracee is only visible to its ptracer").
    * **Nothing reportable, `POLLIN` clear:** `ABSENT` — no termination, so no report: running, sleeping, stopped, uninterruptible or in a debugger's exit stop, alike.
    * **`CLD_TRAPPED`:** suprasole is the tracer (the shell called `PTRACE_TRACEME`). `WNOWAIT` leaves the trap pending, so it is consumed with a `WSTOPPED`-only `waitid`, which can never collect, and the peek repeats.
    * **A termination** (`CLD_EXITED`, `CLD_KILLED` or `CLD_DUMPED`, named positively): `REPORTED`, with the peek's `siginfo`. `CLD_STOPPED` / `CLD_CONTINUED` cannot appear without `WSTOPPED` / `WCONTINUED`; they fall into the final `else`, which panics.
  * **`Zombie_Withheld`:** the pidfd is already readable, so it offers nothing more to wait on. `repeek__TerminationReport_PtyProcess` re-runs the same observation under `Control` every `INTERVAL_REPEEK__PtyProcess` (1 s) until the tracer collects its report or detaches. It is the worker's only timer, and it runs only while a debugger holds the process; the abandon reaper has its own, `INTERVAL_REAP_ABANDONED__PtyProcess`.
  * **`REPORTED`:** `decode__Termination_PtyProcess` → `Zombie{Termination}`; then, inside one Mutex critical section, `collect__PtyProcess` (the only collecting `waitid` — a single call, since `WNOHANG` rules out `EINTR`) and the final write. Anyone who sees a non-final state under the Mutex can trust its PID.
  * **`FAILED`:** `SystemError` — the watching itself failed: `SyscallConn`, the netpoller (`Read`), `Control`, or `ppoll` (`ENOMEM`). `collect__PtyProcess` likewise has no `ECHILD` branch: its final `else` lists `ECHILD` and an empty report (impossible right after a reporting peek) and panics.
  * **End:** close the pidfd, then close `Channel_FinalState`.
  * **`poll__Pidfd`:** `ppoll` with a zero timeout, `EINTR` retried (`poll(2)` does not exempt a zero timeout); returns the `POLLIN` bit as `SET` / `CLEAR`. `POLLIN` means terminated (`pidfd_open(2)`). The status names the bit itself: a pidfd is always pollable, and `read(2)` on it fails with `EINVAL`, so neither "pollable" nor "read status" would be accurate.
  * **Invalid paths (panic):** a report other than `CLD_EXITED` / `CLD_KILLED` / `CLD_DUMPED` reaching the decoder; a reap reporting nothing after the peek reported a termination; a re-peek finding the process not terminated.
  * **Accepted cost:** a process that survives `SIGKILL` (`D` state) never terminates, so its worker stays parked and its state stays — truthfully — `Alive`: one goroutine and one descriptor, no OS thread, CPU or timer.
